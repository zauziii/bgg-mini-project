MINI PROJECT CANVAS                 Title (preliminary):  What Makes a Board Game Great? Mining BoardGameGeek    Group members:    Aoxue Li, Ezeme Onyenezi Innocent , Zhi Zhou       Workshop # :    4  .     

         MOTIVATION  🎯

Target group: Board game hobbyists and newcomers who want to find their next game, but face tens of thousands of titles on BoardGameGeek.

Objectives: New players suffer “choice paralysis”; a high rating does not mean a game fits their group (player count, complexity, playtime). Players also constantly debate: do complex games really rate higher? Are old classics overrated?

How they benefit: A data-driven tool that matches games to their preferences, plus clear, evidence-based answers to those debates.

 DATA COLLECTION  🧩

Data sources: Official BoardGameGeekXML API2, assessed with a free non-commercial developer token from BGG’s applications page. Game IDs come from BGG’s ranking pages (top ~ 1,000 games).

Method: Scripted, rate-limited (~2 requests/sec), resumable collection; 100 games per requests; outputs game.csv with 14 columns (name, year, min/max players, min/max playtime, categories, mechanics, designers, average rating, complexity weight, users rated, Bayesian rating).

Data management plan: RAW → games.csv (one-time collection) → cleaned → games_clean.csv; every script committed to the repo, fully reproducible; dataset stored locally, cited as BoardGameGeek.

PREPROCESSING  🛠

Goals: Turn the messy collected table into an analysis ready dataset; handle multi-value fields, wrong  types and gaps before any modeling.

Cleaning steps: split semicolon separated categories into lists then one-hot encode them; convert rating/complexity strings to numbers; drop duplicates and deleted rows; handle missing playtime/player count/year (impute median where sensible, otherwise flag); check year outliers.

Transformations: One-hot mechanics and categories; engineered features such as number of mechanics, game age, player-range width, log(user-rated); note that Bayesian rating is derived from ratings, so it is used only as a robustness check, never as a model input.

EXPLORATORY DATA ANALYSIS (EDA)  🔎

Steps: Distribution of ratings (how skewed, how rare are 8+ games): complexity distribution; rating vs publication year (rating-inflation question); top categories by both count and median rating; correlation matrix (complexity, rating, users_rated, playtime, players); boxplots of rating by player count and by decade.

Key question to check early: does the famous “complexity vs rating” pattern really hold, or is it an artifact of which games receive enough votes to enter the ranking.

VISUALIZATIONS 📊

Meaningful visualizations: complexity × rating bubble scatter (color = category, size = number of votes, annotated with famous games); rating by decade boxplot; PCA-based “game archetype” map of clusters; top categories by median rating (horizontal bars); correlation heatmap; NMF topic word bars; before/after cleaning chart (missing values).

Interactive visualization: yes. A streamlit app with hover tooltips, filters (player count, complexity, playtime), and a “pick a game → see most similar games with a radar comparison” widget so end users explore by themselves.


LEARNING TASK  🐭
(focus on problem definition)

Problem setting: a mix of supervised and unsupervised tasks.

  1. Supervised/regression: predict a game’s average rating from features. Target: average rating.

  2. Supervised / classification: predict whether a game is top-tier (rating ≥ 7.5).

  3. Unsupervised / clustering: discover game archetypes from mechanics and categories.

  4. Unsupervised / text: topic modelling (NMF) on game descriptions.

  5. Other / recommender: content-based “games like X” via cosine similarity.

Input variables: all collected fields (name text, year, players, playtime, categories, mechanics, complexity).

LEARNING APPROACH  🪤
(focus on solution implementation)

Relevant methods: Ridge/Linear regression and random forest compared on the same split for regression; logistics regression/random forest for classification; k-means for clustering; TF-IDF + NMF for topics; cosine similarity for the recommender.

Evaluation metrics: RMSE/R2/MAE(regression); accuracy/F1/ROC-AUC(classification); silhouette score (clustering); interpretable top words(topics); for the recommender, qualitative validation with well-known games plus a small hold-out of “similar pairs”.

Splitting/Cross-validation: stratified 80/20 train-test split and 5-fold cross-validation; careful to avoid leakage (never use the Bayesian rating as a feature; decide before modeling whether users_rated is a feature or treated as a confounder).


COMMUNICATION OF RESULTS  📢


Deliverable type: an interactive Streamlit web app as the main deliverable, supported by a blog-style summary page and the 3-minute spotlight presentation; a 5-page technical report for the course.

Interface/workflow: app has three parts: 1) Explore: charts with filters; 2) Find similar games: pick a game → recommendations with radar comparison; 3) what makes a game great: our key findings in plain language. The blog post tells the same story for non-technical readers.


DATA PRIVACY AND ETHICAL CONSIDERATIONS  🔐
(if applicable)



Fairness constraints: BGG users are a self-selected community (hobbyist-heavy, mostly English-speaking); ratings are not a random sample of all players. We state this limitation openly and avoid over-claiming general conclusions.

Consent: not needed, only publicly aggregated game metadata and ratings are used.

Pseudonymization/anonymization: no personal data is collected at all; nothing to anonymize.

ADDED VALUE   🎁                           

Is there a possibility for added value from the data we’re planning to use?

Possibility: yes, the same data can serve players, game shops and designers (e.g., what mechanics sell), and our cleaning + modelling pipeline is reusable for future BGG analyses.

What is the added value: evidence-based answers to hobby debates (complexity vs  rating, rating inflation), an archetype map of games, and preference-matched recommendations. None of the existing commercial tools provide this analysis.

How predictions turn into value: the recommender turns similarity scores into concrete “you should try this next” suggestions; the regression/clustering findings turn into practical buying and choosing advice for the end-user.
